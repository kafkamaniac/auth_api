# Auth API

## О проекте

Auth API - это небольшое REST API для регистрации и авторизации пользователей. Проект написан на Python с использованием FastAPI и PostgreSQL.

Реализованы регистрация и вход по логину и паролю, выдача и обновление JWT-токенов, а также основные операции для работы с аккаунтом: просмотр данных, изменение логина и пароля, удаление пользователя.

Для тестирования запросов используется Swagger UI от FastAPI.

## Используемые технологии

- Python
- FastAPI
- PostgreSQL
- Peewee - ORM для работы с БД
- Psycopg 3 - драйвер PostgreSQL
- Pydantic - проверка входных данных
- PyJWT - работа с JWT-токенами
- pwdlib - хеширование паролей (алгоритм Argon2)
- Uvicorn - запуск приложения

## Установка и запуск

### 1. Скачать проект

Скачать проект можно с репозитория (клонировать репозиторий).
Если проект уже находится на компьютере, нужно просто открыть его корневую папку.

### 2. Создать виртуальное окружение

Для Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Настроить PostgreSQL

Необходимо установить PostgreSQL и создать базу данных для проекта. Например:

```sql
CREATE DATABASE auth_api;
```

Далее нужно настроить подключение к базе данных через файл `.env`.

### 5. Создать файл `.env`

В корне проекта нужно создать файл `.env` со следующими настройками:

```dotenv
DB_NAME=auth_api
DB_USER=postgres
DB_PASSWORD=your_database_password
DB_HOST=localhost
DB_PORT=5432

JWT_SECRET=your_secret_key
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_DAYS=7
```

Вместо `your_database_password` указывается пароль пользователя PostgreSQL, а `your_secret_key` нужно заменить на случайный секретный ключ для JWT.

Для примера настроек можно использовать `.env.example`.

### 6. Запустить сервер

Из корневой папки проекта:

```bash
python -m uvicorn app.main:app --reload
```

После запуска:

- API: http://127.0.0.1:8000
- Swagger UI: http://127.0.0.1:8000/docs

## Эндпоинты

Все маршруты имеют префикс `/api`.

| Метод  | Эндпоинт                    | Что делает                    |
| ------ | --------------------------- | ----------------------------- |
| POST   | `/api/auth/register`        | Регистрация пользователя      |
| POST   | `/api/auth/login`           | Вход и получение токенов      |
| POST   | `/api/auth/refresh`         | Обновление токенов            |
| GET    | `/api/user/{user_id}`       | Получение данных пользователя |
| PUT    | `/api/user/{user_id}`       | Изменение логина              |
| PUT    | `/api/auth/update_password` | Изменение пароля              |
| DELETE | `/api/user/{user_id}`       | Удаление аккаунта             |

Для запросов, требующих авторизации, нужно передавать Access Token в заголовке:

```http
Authorization: Bearer <access_token>
```

## Примеры запросов

### Регистрация

`POST /api/auth/register`

```json
{
  "login": "test_user",
  "password": "example_password123"
}
```

### Авторизация

`POST /api/auth/login`

```json
{
  "login": "test_user",
  "password": "example_password123"
}
```

В ответе сервер возвращает Access Token и Refresh Token.

### Обновление токенов

`POST /api/auth/refresh`

```json
{
  "refresh_token": "<refresh_token>"
}
```

В запросе передаётся Refresh Token, полученный при авторизации.

## Проверка работы

Для проверки API можно открыть `/docs`, выбрать нужный эндпоинт и нажать **Try it out**, затем заполнить поля и нажать **Execute**.

Для защищённых запросов сначала нужно авторизоваться и получить Access Token. После этого его можно указать через кнопку **Authorize** в Swagger UI.

## Аргументация выбора технологий

### Аргументация выбора ORM

В качестве ORM используем peewee, так как в сравнении с SQLAlchemy она более проста в освоении, так же поддерживает работу с PostgreSQL и все необходимые операции. Проект – маленький и тестовый, не требует асинхронности, только синхронные операции CRUD по ТЗ. Цель работы – сделать тестовое задание за ограниченное время, поэтому время стоит использовать эффективно. SQLAlchemy подходит для больших проектов и является золотым стандартом для ORM (даже по словам создателя peewee), но в данном проекте будет излишним, однако изучение SQLAlchemy полезно для будущих backend-проектов на python. Драйвером будет Psycopg 3, который peewee также поддерживает.

### Аргументация выбора полей в БД

Для сущности пользователя предусмотрены следующие поля:

- id – первичный ключ, автоматически генерируемый PostgreSQL, используется для однозначной идентификации пользователя.
- login – логин пользователя
- hashed_password – хеш пароля, используемый для проверки подлинности пользователя без хранения исходного пароля с солью

В рамках БД для сущности пользователя были использованы обязательные поля: логин и пароль (хэшированный), также ID, который служит первичным ключом (автоматически генерируется PostgreSQL). Отдельное поле для соли не требуется, так как для хэширования будет использован Argon2, который автоматически генерирует соль и включает её в строку хэша. ТЗ не подразумевает разделение, так как доступ к операциям CRUD имеет только авторизированный пользователь. Однако даже авторизированный пользователь не должен иметь права изменять или удалять других пользователей, поэтому сервер должен проверять, принадлежит ли ему аккаунт (ещё одна причина указывать ID, так как одного JWT-токена может быть недостаточно для обеспечения безопасности).

### Общение с API

Для обмена данными между клиентом и сервером (пункт Общение с API) используется формат данных JSON, так как FastAPI использует его по умолчанию, и данный формат данных является удобным для чтения и оптимальным в рамках поставленной задачи, нет смысла что-то менять. За валидацию и трансформацию данных отвечает библиотека Pydantic, она же обеспечивает преобразование полученных данных в типизированные Python-объекты и подготовку данных к сериализации. Формирование JSON-ответов выполняется средствами FastAPI.
